# One-time MARTIAN test fee recovery

The operator requested recovery of fees generated by their test buys and sells
on 2026-10-04. This is a transfer of available agent funds, not a direct-deposit
refund, AI credit refund, or change to SHEN's 85/15 fee allocation.

The local signer command is fixed to:

- Coin: `0acdcac1-1a5f-4e97-b31e-9eea2a3eaabd` (MARTIAN)
- Token: `0x2e027e343b6359c792B6a061888Bee4362C57777`
- Source: `0x92b3291953bad11b24debccd6e40c8eb6b1b964f`
- Authorized recipient: `0x4a41ee912283966be446514af39e1e3322bb7840`
- Maximum transfer: 0.03 BNB; actual amount is the lesser of this and confirmed
  balance minus verified unpaid SHEN fees, the configured operating gas reserve,
  and this transfer's gas allowance.

Rebuild/redeploy the signer, then use its Dokploy container terminal. The command
uses the existing encrypted wallet database and environment; no credentials or
private keys are printed or entered manually.

Preview without signing or broadcasting:

```sh
node /app/services/signer/recover-martian.mjs --preview
```

Execute the authorized transfer using a freshly checked balance:

```sh
node /app/services/signer/recover-martian.mjs --execute
```

The result reports the actual amount, preserved reserves, transaction hash and
status. `signed` or `broadcast` does not mean confirmed. Run the same `--execute`
command again to reconcile confirmation or rebroadcast the identical saved bytes.
Once confirmed, subsequent runs report the same transfer and cannot withdraw
newly accumulated fees. A reverted transfer is terminal and is not automatically
replaced. Do not delete or edit its journal row or change the fixed recovery ID.

Existing signed payments, active treasury campaigns, domain funding, untracked
pending nonces, or unverified fee reserves stop recovery. Live wallet locks and
the existing encrypted transaction journal protect against competing signatures
and ambiguous broadcast acknowledgements. The ordinary HTTP/model intent API
continues rejecting the `test_recovery` kind and arbitrary recipients.

This command does not pause the agent, cancel jobs, clear uncertain publication
holds, or refund prepaid service credit. After recovery, the agent can continue
using its remaining credit and any future fees. Recovery is recorded in the
signer journal and on-chain; it does not fabricate an agent-approved plan or
credit purchase in the application database.
