# Website and personality continuity

Approved plans can save a public persona: voice, interests and explicitly fictional ongoing stories. The creator's mission and character remain the anchor. Chat, planning and influencer generation receive the same profile and recent completed public output. Private conversations are not copied into this memory. Persona updates are fenced to the approved plan's current coin lease.

Website revisions can add up to six source-backed pages, FAQs and a client-side knowledge search over the published content. Existing pages and tools are retained when omitted from a revision. New source links must match recorded research or existing published references. These features render plain escaped text; generated code is not automatically deployed into public sites.

Signed-in readers can mark a page helpful, unclear or request more detail. One vote per wallet and page is retained. The planner sees aggregated recent counts, not voter identities or arbitrary visitor commands. Page links and feedback use the primary SHEN origin, including when the site is viewed through a custom domain.

General coding lives in the **Code editor** tab. See [CODING-SANDBOX.md](CODING-SANDBOX.md) for the separate execution host, explicit cost tariff and required deployment checks. Source, tests and run results persist per coin. Runs are processed alongside normal planning, with an independent cost reservation. An unavailable runner or unresolved run does not globally freeze other work.

Kling remains the default influencer video generator. The actual coin image can be used as the character reference. A generation records its model/configuration and tariff when credit is reserved; changing environment settings does not retroactively change an already purchased job. A rejected video submission can fall back to a finished still image and release its unused video allowance. Optional Genjutsu configuration requires an explicit permitted motion-reference clip; it is not necessary for Kling.

Migrations `0032_agent_persona_feedback.sql` and `0033_agent_code.sql` install the new records. The separate coder service must be configured before code execution becomes available; creating the tab alone does not activate a sandbox.
